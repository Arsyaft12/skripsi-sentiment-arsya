[Chapter*] Abstrak

[Standard] SentimenAI: Implementasi Metode Naive Bayes dan Support Vector Machine untuk Klasifikasi Sentimen Ulasan Produk E-Commerce Berbasis Hugging Face Datasets dengan Integrasi REST API FastAPI dan Dashboard Next.js
[Standard] Penelitian ini dilatarbelakangi oleh inkonsistensi hasil penelitian terdahulu dalam membandingkan performa algoritma Naive Bayes dan Support Vector Machine (SVM) pada data ulasan berbahasa Indonesia, sehingga diperlukan pengujian ulang secara empiris pada dataset yang terstandarisasi. Penelitian ini bertujuan mengimplementasikan dan membandingkan kedua metode tersebut, membangun REST API berbasis FastAPI, mengembangkan dashboard interaktif berbasis Next.js yang dilengkapi fitur Generate Insight berbasis Large Language Model, serta menyediakan penyimpanan riwayat analisis berbasis SQLite, sehingga hasil validasi algoritma tidak berhenti sebagai angka di dalam laporan penelitian, melainkan terwujud sebagai sistem yang dapat digunakan secara nyata.
[Standard] Metode penelitian menggunakan model pengembangan ADDIE, dengan dataset sepidmnorozy/Indonesian_sentiment dari Hugging Face Datasets (10.192 data), preprocessing empat tahap (case folding, penghapusan karakter, stopword removal, dan stemming menggunakan PySastrawi), ekstraksi fitur TF-IDF (ngram 1-2, 10.000 fitur), serta pelatihan model Multinomial Naive Bayes dan LinearSVC. Pengujian sistem dilakukan secara berlapis meliputi black box testing, white box testing, boundary testing, 5-fold cross validation, hyperparameter tuning menggunakan GridSearchCV, ablasi pengaruh preprocessing, error analysis, pengukuran response time API, dan heuristic evaluation.
[Standard] Hasil penelitian menunjukkan SVM mengungguli Naive Bayes dengan akurasi 88,44% (presisi 88,35%, recall 88,44%, F1-score 88,36%) dibandingkan 87,56% pada Naive Bayes, konsisten pada pengujian 5-fold cross validation (standar deviasi ±0,29%). Hyperparameter tuning meningkatkan akurasi SVM menjadi 89,19%. Studi ablasi menemukan bahwa stopword removal menurunkan akurasi hingga 3,36 poin persentase karena turut menghapus kata negasi. Sistem berhasil diimplementasikan dengan enam belas endpoint REST API dan response time median 6,51 milidetik, serta dashboard dengan empat tab fungsional dan halaman Generate Insight.
[Standard] Kata Kunci: Naive Bayes, Support Vector Machine, Analisis Sentimen, FastAPI, Next.js

[Chapter*] Abstract
[Plain] status collapsed addcontentsline{toc}{chapter}{Abstract}
[Standard] SentimenAI: Implementation of Naive Bayes and Support Vector Machine Methods for E-Commerce Product Review Sentiment Classification Based on Hugging Face Datasets with FastAPI REST API Integration and Next.js Dashboard
[Standard] This research is motivated by the inconsistency of prior studies in comparing the performance of Naive Bayes and Support Vector Machine (SVM) algorithms on Indonesian-language review data, which calls for a renewed empirical evaluation on a standardized dataset. This study aims to implement and compare both methods, build a FastAPI-based REST API, develop an interactive Next.js dashboard equipped with a Large Language Model-based Generate Insight feature, and provide SQLite-based analysis history storage, so that the algorithm validation results do not merely remain as figures in a research report but are realized as a genuinely usable system.
[Standard] The research method employed the ADDIE development model, using the sepidmnorozy/Indonesian_sentiment dataset from Hugging Face Datasets (10,192 data points), a four-stage preprocessing pipeline (case folding, character removal, stopword removal, and stemming using PySastrawi), TF-IDF feature extraction (1-2 ngram range, 10,000 features), and training of Multinomial Naive Bayes and LinearSVC models. System testing was conducted in multiple layers, including black box testing, white box testing, boundary testing, 5-fold cross validation, hyperparameter tuning using GridSearchCV, preprocessing ablation, error analysis, API response time measurement, and heuristic evaluation.
[Standard] The results show that SVM outperformed Naive Bayes with an accuracy of 88.44% (precision 88.35%, recall 88.44%, F1-score 88.36%) compared to 87.56% for Naive Bayes, remaining consistent under 5-fold cross validation (standard deviation ±0.29%). Hyperparameter tuning improved SVM accuracy to 89.19%. The ablation study found that stopword removal decreased accuracy by up to 3.36 percentage points because it also removed negation words. The system was successfully implemented with twelve REST API endpoints and a median response time of 6.51 milliseconds, along with a dashboard featuring four functional tabs and a Generate Insight page.
[Standard] Keywords: Naive Bayes, Support Vector Machine, Sentiment Analysis, FastAPI, Next.js

[Section] Latar Belakang
[Standard] Penelitian ini secara eksplisit berangkat dari satu celah penelitian ( research gap ) yang konkret, bukan dari ketertarikan umum terhadap analisis sentimen semata. Celah tersebut adalah: belum ada penelitian yang menguji ulang performa Naive Bayes dan Support Vector Machine pada dataset ulasan berbahasa Indonesia yang terstandarisasi dan dapat direproduksi melalui Hugging Face Datasets , sekaligus membuktikan hasil pengujian tersebut pada sebuah sistem yang benar-benar beroperasi (bukan sekadar notebook eksperimen). Kedua sisi celah ini, sisi keilmuan (validitas empiris algoritma) dan sisi rekayasa (kelayakan produksi), akan ditunjukkan secara berurutan pada paragraf-paragraf berikut, dan menjadi benang merah yang menyatukan seluruh rumusan masalah dan tujuan penelitian pada Sub-bab 1.2 dan 1.4.
[Standard] Pertumbuhan transaksi belanja daring di Indonesia dalam satu dekade terakhir telah mengubah pola interaksi antara konsumen dan pelaku usaha. Setiap transaksi yang terjadi di platform e-commerce hampir selalu diikuti oleh satu jejak digital yang sederhana namun bernilai tinggi: ulasan produk. Ulasan ini bukan sekadar komentar, melainkan representasi langsung dari pengalaman konsumen terhadap kualitas produk, kecepatan pengiriman, dan pelayanan penjual. Ketika volume ulasan bertambah hingga ribuan per bulan untuk satu toko sekalipun, kemampuan manusia untuk membaca dan menyimpulkan kecenderungan sentimen secara manual menjadi tidak realistis. Dari kebutuhan inilah analisis sentimen, yaitu proses klasifikasi opini teks ke dalam kategori positif atau negatif secara otomatis, menjadi relevan untuk dikaji dan diimplementasikan.
[Standard] Dua algoritma klasifikasi yang paling sering dijadikan rujukan dalam penelitian analisis sentimen berbahasa Indonesia adalah Naive Bayes dan Support Vector Machine (SVM). Kedua algoritma ini dipilih bukan tanpa alasan: keduanya ringan secara komputasi, tidak memerlukan data berlabel dalam jumlah masif seperti model deep learning , dan telah terbukti bekerja baik pada data teks berdimensi tinggi hasil representasi TF-IDF. Namun demikian, penelusuran terhadap penelitian-penelitian terdahulu justru menunjukkan hasil yang saling bertolak belakang, dan di sinilah letak sisi pertama dari celah penelitian yang disebutkan di paragraf pembuka. Sanjaya, Fauzi, dan Masruriyah (2023) yang meneliti 2.000 ulasan Shopee melaporkan bahwa Naive Bayes justru mengungguli SVM, dengan akurasi 85% berbanding 81% dan nilai AUC 0,855 berbanding 0,810. Sebaliknya, Apriyani, Nur, dan Astuti (2024) yang meneliti ulasan aplikasi Mobile JKN menemukan bahwa SVM secara konsisten mengungguli Naive Bayes pada seluruh skenario pembagian data latih dan uji (70:30, 80:20, dan 90:10), dengan keunggulan yang paling menonjol pada aspek presisi. Temuan yang lebih ekstrem datang dari penelitian Zahra, dkk. (2026) pada 65.335 ulasan Tokopedia, di mana Linear SVC mencapai akurasi 97,60%, jauh meninggalkan Naive Bayes maupun model IndoBERT yang telah di-fine-tune sekalipun.
[Standard] Pertentangan hasil di atas mengarah pada satu simpulan penting: performa relatif antara Naive Bayes dan SVM sangat bergantung pada karakteristik dataset yang digunakan, mulai dari ukuran data, keseimbangan kelas, hingga gaya bahasa ulasan itu sendiri. Konsekuensinya, klaim keunggulan salah satu algoritma dari satu penelitian tidak dapat digeneralisasi begitu saja ke konteks data lain. Hal ini menjadi celah penelitian ( research gap ) yang mendasari perlunya pengujian ulang kedua algoritma tersebut secara khusus pada data ulasan e-commerce berbahasa Indonesia yang terstandarisasi, alih-alih hanya mengutip hasil dari penelitian lain.
[Standard] Untuk menjamin data yang digunakan benar-benar terstandarisasi dan dapat direproduksi oleh peneliti lain, penelitian ini memanfaatkan Hugging Face Datasets sebagai sumber data. Lhoest, dkk. (2021) menjelaskan bahwa Datasets dirancang khusus untuk mengatasi persoalan standardisasi, versioning, dan dokumentasi yang selama ini menjadi kendala dalam penelitian NLP; setiap dataset diakses melalui satu baris kode, dikunci pada versi tertentu, dan didukung lebih dari 650 dataset publik yang telah didokumentasikan komunitas. Dataset sepidmnorozy/Indonesian_sentiment yang tersedia pada platform ini dipilih karena telah berisi ulasan produk berbahasa Indonesia dengan label biner yang siap pakai, sehingga penelitian ini dapat berfokus pada perbandingan algoritma tanpa harus menanggung bias dari proses pelabelan manual seperti yang dihadapi banyak penelitian lain.
[Standard] Selain isu perbandingan algoritma, penelusuran pustaka juga menunjukkan sisi kedua dari celah penelitian yang disebutkan di paragraf pembuka: sebagian besar penelitian analisis sentimen berhenti pada tahap pelaporan angka akurasi di dalam artikel ilmiah, tanpa membungkusnya menjadi sebuah sistem yang benar-benar dapat digunakan. Danyal, dkk. (2023) misalnya, membandingkan delapan algoritma pada dua dataset ulasan film berbahasa Inggris dan berhasil menunjukkan Linear SVM unggul pada dataset besar (89,48%) sedangkan Multinomial Naive Bayes unggul pada dataset yang lebih kecil dan sulit (70,69%), namun kontribusi tersebut berhenti sebagai perbandingan model di atas kertas. Demikian pula Ali, dkk. (2024) yang menguji delapan pendekatan machine learning , deep learning , hingga transformer (BERT, XLNet) pada 400.000 ulasan Amazon, memperoleh BERT sebagai model terbaik (89%) namun laporan tersebut tetap berhenti pada tahap eksperimen offline. Padahal, agar hasil klasifikasi sentimen benar-benar bermanfaat bagi pelaku bisnis e-commerce , model yang telah dilatih perlu dibungkus dalam layanan yang dapat diakses secara real-time , ditampilkan secara visual, dan dapat diaudit riwayatnya.
[Standard] Kebutuhan inilah yang mendorong penelitian ini untuk tidak berhenti pada pelatihan dan evaluasi model, melainkan melanjutkannya menjadi sebuah sistem utuh bernama SentimenAI. Model Naive Bayes dan SVM yang telah dilatih dibungkus ke dalam REST API menggunakan FastAPI, mengikuti pola integrasi yang juga diterapkan Maulyanda dan Nazhifah (2025) yang membuktikan SVM dapat diintegrasikan langsung ke FastAPI untuk analisis sentimen kesehatan mental, kemudian disajikan melalui dashboard interaktif berbasis Next.js yang memanfaatkan kemampuan server-side rendering untuk performa pemuatan halaman yang lebih baik (Jartarghar, dkk.). Pendekatan menggabungkan model klasik dengan infrastruktur data modern (Hugging Face) dan antarmuka web modern (Next.js dan FastAPI) inilah yang menjadi pembeda penelitian ini dari sekadar replikasi perbandingan algoritma yang sudah banyak dilakukan sebelumnya.
[Standard] Sebagai pembanding tambahan atas relevansi pilihan metode, penelitian Latifah, dkk. (2026) pada data opini kebijakan Tapera menunjukkan bahwa untuk dataset berskala kecil hingga menengah (di bawah 12.000 sampel), kombinasi pelabelan berbasis leksikon dengan model machine learning klasik seperti Naive Bayes dan Random Forest tetap memberikan hasil yang solid (di atas 85%) dengan biaya komputasi yang jauh lebih efisien dibandingkan model Transformer, yang justru membutuhkan penyesuaian ( fine-tuning ) yang cermat agar dapat bersaing. Temuan ini memperkuat posisi penelitian ini yang memilih Naive Bayes dan SVM sebagai fondasi utama sistem, bukan karena ketertinggalan teknologi, melainkan karena pertimbangan efisiensi dan kelayakan praktis untuk diimplementasikan sebagai layanan API yang responsif.
[Standard] Berdasarkan seluruh uraian di atas, penelitian ini dirancang dengan tiga niat yang saling berkaitan: pertama, menguji ulang secara empiris performa Naive Bayes dan SVM pada dataset ulasan e-commerce Indonesia yang terstandarisasi dari Hugging Face, mengingat hasil penelitian terdahulu yang tidak konsisten; kedua, membuktikan bahwa kedua algoritma klasik tersebut tetap layak dan efisien untuk dibungkus menjadi layanan REST API produksi, bukan sekadar model eksperimen di notebook; dan ketiga, menghadirkan lapisan interpretasi tambahan berbasis Large Language Model (Gemini API) pada dashboard , sehingga keluaran sistem tidak berhenti pada angka dan label, melainkan dapat langsung dipahami dan ditindaklanjuti oleh pengguna non-teknis seperti tim manajemen atau pemasaran e-commerce .

[Section] Batasan Masalah
[Quote] 1. Dataset ulasan yang digunakan bersumber dari Hugging Face Datasets , khususnya dataset sepidmnorozy/Indonesian_sentiment yang berisi ulasan produk berbahasa Indonesia berlabel biner (positif dan negatif), dan tidak mencakup pengumpulan data langsung dari platform e-commerce melalui web scraping .
[Quote] 2. Sistem mendukung dua jenis input : teks ulasan tunggal secara manual melalui antarmuka dashboard , dan upload berkas CSV berisi kumpulan ulasan untuk pemrosesan batch massal.
[Quote] 3. Klasifikasi sentimen terbatas pada dua kategori: positif (label=1) dan negatif (label=0), sesuai label yang tersedia pada dataset sepidmnorozy/Indonesian_sentiment; penelitian ini tidak mencakup klasifikasi tiga kelas (dengan kategori netral) sebagaimana yang dilakukan pada beberapa penelitian pembanding (Ali dkk., 2024; Zahra dkk., 2026).
[Quote] 4. Metode klasifikasi yang dibandingkan terbatas pada Multinomial Naive Bayes dan LinearSVC (SVM kernel linear); metode deep learning maupun pretrained language model seperti IndoBERT tidak dilatih ulang dalam penelitian ini, namun hasilnya pada penelitian lain (Ali dkk., 2024; Zahra dkk., 2026; Latifah dkk., 2026) tetap dijadikan bahan pembanding pada pembahasan.
[Quote] 5. Fitur tanya-jawab pada halaman Generate Insight menggunakan Large Language Model eksternal (Google Gemini API) yang berperan sebagai lapisan interpretasi naratif atas data hasil klasifikasi yang sudah ada; LLM tidak digunakan sebagai metode klasifikasi sentimen utama.
[Quote] 6. Pengembangan sistem menggunakan Python 3.12, FastAPI 0.109.0, scikit-learn 1.4.0, PySastrawi 1.2.0, SQLite (bawaan Python), Next.js 14.2.35, Re chart s, dan Axios sebagai stack teknologi utama.
[Quote] 7. Penyimpanan data menggunakan SQLite sebagai basis data lokal berbasis berkas; sistem tidak menggunakan basis data server seperti PostgreSQL atau MySQL.
[Quote] 8. Pengujian sistem dilakukan menggunakan black box testing untuk fungsionalitas, white box testing untuk memverifikasi tahapan preprocessing, k-fold cross validation untuk stabilitas model, dan confusion matrix untuk evaluasi performa klasifikasi.
[Quote] 9. Sistem dijalankan pada lingkungan lokal (localhost) dan tidak mencakup deployment ke server produksi atau layanan cloud .
[Section] Tujuan Penelitian
[Standard] Sejalan dengan celah penelitian yang telah diuraikan pada Sub-bab 1.1, penelitian ini memiliki satu tujuan besar yang tunggal: membangun dan membuktikan secara empiris bahwa sistem klasifikasi sentimen berbasis Naive Bayes dan SVM dapat direalisasikan secara utuh, dari validasi algoritma hingga menjadi layanan produksi yang dapat diakses dan diaudit. Kelima poin di bawah ini bukan lima penelitian yang berdiri sendiri, melainkan lima tahapan berurutan untuk mencapai satu tujuan besar tersebut: dimulai dari implementasi model (poin 1), dilanjutkan pembuktian keunggulan model melalui pengujian empiris (poin 2), kemudian dibungkus menjadi layanan API (poin 3), disajikan melalui antarmuka pengguna (poin 4), dan ditutup dengan mekanisme penyimpanan data yang menopang seluruh tahapan sebelumnya (poin 5).
[Quote] 1. Mengimplementasikan metode Multinomial Naive Bayes dan Support Vector Machine (LinearSVC) untuk klasifikasi sentimen ulasan produk e-commerce berbasis dataset sepidmnorozy/Indonesian_sentiment dari Hugging Face Datasets melalui tahapan case folding , penghapusan karakter khusus, stopword removal PySastrawi, stemming morfologis, dan ekstraksi fitur TF-IDF.
[Quote] 2. Membandingkan performa Naive Bayes dan SVM berdasarkan metrik akurasi, presisi, recall, dan F1-score untuk memperoleh bukti empiris baru pada konteks data ulasan e-commerce berbahasa Indonesia, mengingat inkonsistensi hasil pada penelitian-penelitian terdahulu.
[Quote] 3. Merancang dan mengimplementasikan REST API berbasis FastAPI 0.109.0 yang menyajikan layanan mencakup prediksi sentimen tunggal, perbandingan dual model, preprocessing step-by-step, pemrosesan batch CSV eksternal, riwayat analisis, statistik sentimen, evaluasi model, integrasi Large Language Model, dan dokumentasi Swagger/OpenAPI lengkap.
[Quote] 4. Mengembangkan dashboard interaktif berbasis Next.js 14 yang memvisualisasikan hasil klasifikasi secara real-time menggunakan Re chart s, menampilkan detail preprocessing step-by-step, distribusi sentimen, perbandingan model, serta halaman Generate Insight yang dilengkapi kolom tanya-jawab berbasis Gemini API untuk rekomendasi strategis kontekstual.
[Quote] 5. Merancang sistem penyimpanan riwayat analisis menggunakan database SQLite yang memastikan data tersimpan permanen, tidak hilang saat server di-restart, dapat diakses melalui endpoint /riwayat dan /statistik untuk kebutuhan audit dan pelaporan, serta berfungsi sebagai sumber konteks data real-time bagi fitur tanya-jawab Generate Insight.
[Section] Manfaat Penelitian
[Subsection] Manfaat Teoritis
[Standard] Secara teoritis, penelitian ini memberikan bukti empiris tambahan pada perdebatan performa Naive Bayes versus SVM dalam konteks data ulasan e-commerce berbahasa Indonesia, sekaligus menjadi rujukan bagi penelitian selanjutnya mengenai integrasi model machine learning klasik ke dalam arsitektur REST API modern dan dashboard berbasis Next.js.
[Subsection] Manfaat Praktis
[Standard] Secara praktis, sistem SentimenAI dapat digunakan oleh pelaku usaha e-commerce skala kecil hingga menengah untuk memantau sentimen pelanggan secara mandiri tanpa memerlukan tim data science internal, sekaligus memperoleh rekomendasi strategis naratif melalui fitur Generate Insight yang membantu pengambilan keputusan berbasis data.

[Chapter] Tinjauan Pustaka
[Section] Penelitian Terdahulu
[Standard] Bagian ini menelaah sembilan rujukan utama yang menjadi dasar pijakan penelitian, mulai dari penelitian yang secara langsung membandingkan Naive Bayes dan SVM pada berbagai domain ulasan, penelitian yang membangun infrastruktur data (Hugging Face Datasets ), hingga penelitian yang menyentuh sisi rekayasa perangkat lunak (Next.js). Penelaahan dilakukan bukan sekadar merangkum satu per satu, melainkan juga membandingkan temuan antar penelitian untuk menunjukkan di titik mana penelitian ini memiliki kebaruan.
[Subsubsection] Perbandingan Naive Bayes dan SVM pada Ulasan Shopee (Sanjaya, Fauzi, & Masruriyah, 2023)
[Standard] Penelitian yang dimuat pada jurnal INFOTECH ini mengumpulkan 2.000 ulasan produk dari marketplace Shopee melalui teknik scraping , kemudian membaginya dengan rasio 80:20 untuk data latih dan data uji. Tahapan preprocessing yang diterapkan meliputi case folding , tokenizing , filtering (penghapusan stopword), dan stemming , sebelum data diubah menjadi representasi numerik menggunakan TF-IDF. Visualisasi Word Cloud turut digunakan untuk menampilkan kata-kata yang paling sering muncul pada masing-masing kelas sentimen. Hasil pengujian menunjukkan Naive Bayes memperoleh akurasi 85% dengan nilai AUC 0,855, mengungguli SVM yang hanya mencapai akurasi 81% dengan AUC 0,810. Sanjaya, dkk. berargumen bahwa keunggulan Naive Bayes ini terjadi karena asumsi independensi antar kata pada model probabilistik tersebut ternyata cukup relevan dengan pola kata pada ulasan singkat khas marketplace, di mana korelasi antar kata tidak terlalu kompleks. Bagi penelitian ini, temuan Sanjaya dkk. menjadi salah satu argumen kunci yang menunjukkan bahwa Naive Bayes tidak boleh dipandang sebelah mata hanya karena kesederhanaan modelnya, sehingga kedua algoritma tetap layak diuji secara berimbang, bukan diasumsikan salah satu lebih unggul sejak awal.
[Subsubsection] Klasifikasi Multi-Kelas pada Ulasan Amazon dengan Machine Learning, Deep Learning, dan Transformer (Ali, Hashmi, Yayilgan, & Shaikh, 2024)
[Standard] Berbeda dari penelitian Sanjaya dkk. yang berskala kecil, penelitian yang dipublikasikan pada jurnal Electronics (MDPI) ini menguji delapan pendekatan sekaligus pada 400.000 ulasan Amazon lintas lima kategori produk, mencakup model machine learning klasik (Multinomial Naive Bayes, Random Forest, Decision Tree, Logistic Regression), model ensemble (bagging), model deep learning (CNN, BiLSTM), hingga model transformer (BERT dan XLNet) untuk klasifikasi sentimen tiga kelas (positif, netral, negatif). Hasil penelitian menunjukkan BERT sebagai model dengan performa terbaik dengan akurasi 89%, mengungguli seluruh model klasik maupun deep learning lainnya, bahkan melampaui hasil penelitian pembanding lain pada dataset serupa yang hanya mencapai akurasi 71,5%. Ali, dkk. juga menerapkan teknik interpretability LIME untuk menjelaskan kata-kata yang paling memengaruhi keputusan klasifikasi model, serta melakukan analisis kesalahan ( error analysis ) untuk memahami pola ulasan yang sering salah diklasifikasikan, terutama pada kelas netral yang secara linguistik memang paling ambigu. Penelitian ini menjadi rujukan penting untuk menunjukkan batas atas performa yang secara teoritis dapat dicapai apabila model yang jauh lebih kompleks digunakan, sekaligus mengingatkan bahwa kompleksitas tersebut datang dengan konsekuensi biaya komputasi yang tidak sebanding untuk sistem berskala kecil-menengah seperti yang menjadi sasaran penelitian ini.
[Subsubsection] Hugging Face Datasets: Standardisasi Dataset untuk Riset NLP (Lhoest dkk., 2021)
[Standard] Penelitian ini berbeda karakter dari dua penelitian sebelumnya karena tidak membahas algoritma klasifikasi, melainkan membahas infrastruktur data yang mendasari penelitian NLP modern. Dipublikasikan pada prosiding EMNLP: System Demonstrations, Lhoest, dkk. memperkenalkan pustaka Hugging Face Datasets yang dirancang untuk mengatasi tiga persoalan utama riset NLP: kurangnya standardisasi format dataset , sulitnya menelusuri versi dataset yang digunakan pada suatu eksperimen, serta minimnya dokumentasi ( data card ) yang menyertai dataset publik. Pustaka ini dibangun di atas format kolumnar Apache Arrow sehingga mampu memuat dataset berukuran sangat besar tanpa membebani memori ( memory-mapping dan streaming ), serta pada saat publikasi telah mendukung lebih dari 650 dataset dan puluhan metrik evaluasi yang dikurasi komunitas. Lhoest, dkk. turut menunjukkan studi kasus penggunaan Datasets pada proyek benchmarking multi-tugas seperti GEM dan Robustness Gym untuk membuktikan reprodusibilitas eksperimen lintas peneliti. Bagi penelitian ini, karya Lhoest dkk. menjadi landasan metodologis langsung karena dataset sepidmnorozy/Indonesian_sentiment yang digunakan diakses melalui pustaka yang sama, sehingga proses pemuatan data pada penelitian ini terjamin konsisten dan dapat direproduksi oleh peneliti lain dengan satu baris kode yang sama persis.
[Subsubsection] Perbandingan Algoritma Klasik pada Ulasan Film Berbahasa Inggris (Danyal, Khan, Khan, Ghaffar, Khan, & Arshad, 2023)
[Standard] Dipublikasikan pada Journal of Big Data, penelitian ini menguji delapan algoritma klasik, termasuk Linear SVM (LSVM) dan Multinomial Naive Bayes (MNB), pada dua dataset ulasan film berbahasa Inggris, yaitu IMDB (50.000 ulasan) dan Sentiment Polarity v2.0 milik Pang dan Lee. Preprocessing yang diterapkan cukup menyeluruh, meliputi pembersihan teks, stemming menggunakan algoritma Snowball, normalisasi huruf, hingga penanganan kata gaul ( chat word treatment ) sebelum representasi TF-IDF dibentuk. Hasil penelitian menunjukkan pola yang menarik dan relevan bagi penelitian ini: pada dataset IMDB yang besar dan relatif bersih, LSVM tampil sebagai model terbaik dengan akurasi 89,48% (meningkat menjadi 89,96% setelah hyperparameter tuning ), sedangkan pada dataset Sentiment Polarity v2.0 yang lebih kecil dan lebih menantang, justru MNB yang tampil terbaik dengan akurasi 70,69% (meningkat menjadi 71,04% setelah tuning). Danyal, dkk. menyimpulkan bahwa ukuran dan kompleksitas dataset menjadi faktor penentu utama algoritma mana yang lebih unggul, bukan superioritas algoritma itu sendiri secara mutlak. Simpulan inilah yang secara langsung menguatkan argumen penelitian ini bahwa perbandingan Naive Bayes dan SVM perlu dilakukan ulang secara spesifik pada karakteristik dataset ulasan e-commerce Indonesia, alih-alih mengasumsikan hasil dari dataset berbahasa Inggris akan berlaku sama.
[Subsubsection] Perbandingan Naive Bayes dan SVM pada Ulasan Aplikasi Mobile JKN (Apriyani, Nur, & Astuti, 2024)
[Standard] Penelitian yang dimuat pada Knowbase Journal ini paling dekat konteksnya dengan penelitian ini karena sama-sama berfokus pada data berbahasa Indonesia dan sama-sama membandingkan Naive Bayes dengan SVM. Data penelitian berupa 200 ulasan aplikasi Mobile JKN yang diambil dari Twitter dan diberi label secara manual oleh dua orang penilai (rater) untuk menjaga validitas label. Tahapan preprocessing mencakup cleansing, case folding , normalisasi kata baku mengacu pada KBBI, tokenizing , penghapusan stopword, dan stemming , sebelum representasi TF-IDF dibentuk. Pengujian dilakukan pada tiga rasio pembagian data (70:30, 80:20, dan 90:10) untuk melihat konsistensi hasil. Hasil penelitian menunjukkan SVM secara konsisten mengungguli Naive Bayes pada seluruh rasio pembagian data, dengan performa terbaik pada rasio 80:20 yang mencapai presisi hingga 93-100% tergantung penilai yang menjadi acuan label, sedangkan Naive Bayes cenderung memiliki recall yang tinggi namun presisi yang lebih rendah, mengindikasikan model tersebut lebih sering melakukan false positive. Berbeda dengan Sanjaya, dkk. (2023) yang menemukan Naive Bayes lebih unggul pada ulasan Shopee, penelitian Apriyani, dkk. justru menunjukkan hasil sebaliknya pada konteks data yang juga berbahasa Indonesia. Kontradiksi langsung antara dua penelitian berbahasa Indonesia inilah yang menjadi motivasi paling kuat bagi penelitian ini untuk tidak berasumsi dan melakukan pengujian mandiri.
[Subsubsection] Benchmarking Model Klasik dan IndoBERT pada Ulasan Tokopedia (Zahra, Farhanatussaidah, Afifah, Muthoharoh, Satria, & Manullang, 2026)
[Standard] Penelitian pracetak (arXiv) yang paling baru ini menguji empat pendekatan sekaligus, yaitu Logistic Regression, Linear SVC, Multinomial Naive Bayes, dan model IndoBERT yang di-fine-tune, pada 65.335 ulasan produk Tokopedia tahun 2025 yang diambil dari Kaggle dengan tiga label sentimen (positif, netral, negatif). Preprocessing yang diterapkan relatif ringan ( lowercasing , penghapusan URL, penghapusan karakter non-alfanumerik, dan normalisasi spasi) karena representasi TF-IDF dengan kombinasi unigram dan bigram (ngram_range 1-2, max_features 50.000) serta penyeimbangan kelas ( class_weight balanced ) diandalkan untuk menangani ketidakseimbangan data. Hasil penelitian menunjukkan Linear SVC tampil sebagai model terbaik secara mengejutkan dengan akurasi 97,60%, jauh melampaui Multinomial Naive Bayes yang meski memiliki akurasi tinggi namun memiliki F1-score makro yang rendah (0,329) akibat sangat sensitif terhadap ketidakseimbangan kelas, bahkan melampaui IndoBERT yang di-fine-tune (akurasi 88,70%, F1-score makro 0,509) yang performanya tertahan karena keterbatasan ukuran subset data latih yang digunakan untuk fine-tuning . Zahra, dkk. turut mendemonstrasikan penerapan model terbaik pada layanan Gradio yang di- deploy melalui Hugging Face Spaces. Penelitian ini menjadi bukti paling mutakhir dan paling meyakinkan bagi penelitian ini bahwa model klasik seperti SVM, ketika direpresentasikan dengan fitur TF-IDF yang tepat, masih mampu bersaing bahkan mengungguli model Transformer pada data ulasan e-commerce berskala besar, sekaligus menjadi preseden praktik baik bagi pembungkusan model ke dalam layanan yang dapat diakses publik, sebagaimana yang diadaptasi penelitian ini melalui REST API FastAPI dan dashboard Next.js.
[Subsubsection] Strategi Pelabelan Otomatis untuk Analisis Sentimen Berbahasa Indonesia (Latifah, Handayanto, Dwi M.S, Bhandari, Hien, & Pirnazarov, 2026)*-
[Standard] Penelitian yang dimuat pada jurnal ASSET ini mengangkat persoalan yang jarang disorot penelitian analisis sentimen lain, yaitu bagaimana strategi pelabelan data memengaruhi performa model akhir, menggunakan studi kasus 8.447 twit terkait kebijakan Tapera. Latifah, dkk. membandingkan dua strategi pelabelan otomatis, yaitu leksikon InSet dan pipeline IndoBERT bawaan Hugging Face, yang kemudian masing-masing dipasangkan dengan beberapa model klasifikasi. Hasil penelitian menunjukkan kombinasi label InSet dengan model klasik seperti Naive Bayes dan Random Forest yang direpresentasikan TF-IDF memberikan akurasi di atas 85% dengan F1-score antara 0,89 hingga 0,95, sedangkan kombinasi label InSet dengan model RNN-LSTM memang mencapai akurasi di atas 90% namun menuntut sumber daya komputasi yang jauh lebih besar. Menariknya, kombinasi label hasil pipeline Hugging Face dengan representasi TF-IDF pada model Random Forest maupun LSTM justru menghasilkan performa yang buruk (hanya 0,6 hingga 0,7), yang oleh Latifah, dkk. dijelaskan terjadi karena representasi TF-IDF gagal menangkap konteks kalimat yang justru menjadi kekuatan utama label berbasis Transformer; performa baru membaik signifikan ketika IndoBERT di-fine-tune langsung menggunakan label dari pipeline tersebut. Simpulan penelitian ini menegaskan bahwa untuk dataset berskala kecil hingga menengah, kombinasi leksikon dengan model klasik tetap menjadi pilihan yang efisien dan kompetitif, sebuah argumen yang relevan langsung dengan pemilihan Naive Bayes dan SVM pada penelitian ini.
[Subsubsection] Peningkatan Performa Web Menggunakan Server-Side Rendering pada Next.js (Jartarghar, Salanke, A.R, G.S, & Dalali)
[Standard] Berbeda dari delapan rujukan lain yang berfokus pada sisi algoritma dan data, penelitian yang dimuat pada Journal of Telecommunication, Electronic and Computer Engineering (JTEC) ini membahas sisi rekayasa perangkat lunak, khususnya keunggulan pendekatan server-side rendering (SSR) yang ditawarkan framework Next.js dibandingkan pendekatan client-side rendering (CSR) konvensional pada aplikasi berbasis React. Penelitian ini menunjukkan bahwa SSR mampu mempercepat waktu pemuatan konten pertama (First Contentful Paint) dan memperbaiki keterindeksan mesin pencari (SEO), karena markup halaman telah dirender di sisi server sebelum dikirim ke klien, alih-alih menunggu seluruh berkas JavaScript diunduh dan dieksekusi di peramban terlebih dahulu sebagaimana pada aplikasi React murni. Argumen inilah yang menjadi salah satu pertimbangan teknis penelitian ini dalam memilih Next.js sebagai kerangka kerja frontend dashboard SentimenAI, mengingat dashboard perlu memuat data statistik dan grafik dalam volume yang tidak sedikit secara responsif bagi pengguna.
[Subsubsection] Integrasi SVM ke FastAPI untuk Analisis Sentimen Kesehatan Mental (Maulyanda & Nazhifah, 2025)
[Standard] Penelitian yang dimuat pada jurnal Brilliance: Research of Artificial Intelligence ini paling relevan dengan sisi rekayasa perangkat lunak penelitian ini, karena secara khusus membahas integrasi model SVM ke dalam REST API berbasis FastAPI untuk analisis sentimen ulasan terkait kesehatan mental. Maulyanda dan Nazhifah mendemonstrasikan bahwa model SVM yang telah dilatih dapat dibungkus menjadi endpoint prediksi yang responsif menggunakan FastAPI, lengkap dengan dokumentasi otomatis Swagger/OpenAPI, tanpa memerlukan penyesuaian arsitektur model yang signifikan. Penelitian tersebut menunjukkan bahwa FastAPI, dengan validasi data otomatis berbasis Pydantic, mampu menjaga konsistensi format data antara proses pelatihan model dan proses inferensi pada waktu nyata ( real-time inference), sebuah pola yang secara langsung direplikasi pada implementasi endpoint /prediksi penelitian ini (Sub-bab 3.1.3.3). Berbeda dari penelitian Maulyanda dan Nazhifah yang berfokus pada satu domain (kesehatan mental) dan satu model (SVM saja), penelitian ini memperluas pola integrasi tersebut menjadi enam belas endpoint yang mencakup dua model sekaligus (NB dan SVM) serta lapisan interpretasi tambahan berbasis Large Language Model, sebagaimana dirinci pada Tabel 3.1.
[Subsection] Sintesis dan Posisi Penelitian
[Standard] Apabila kesembilan penelitian di atas dirangkai, tergambar satu benang merah yang jelas. Pada sisi algoritma, hasil perbandingan Naive Bayes dan SVM ternyata tidak pernah konsisten di penelitian-penelitian ini; Sanjaya, dkk. (2023) memenangkan Naive Bayes pada ulasan Shopee, Apriyani, dkk. (2024) memenangkan SVM pada ulasan Mobile JKN, Danyal, dkk. (2023) menemukan pemenang berbeda tergantung ukuran dataset , dan Zahra, dkk. (2026) memenangkan SVM secara telak pada dataset besar Tokopedia. Pola yang sama juga berulang pada perbandingan model klasik dengan Transformer: Ali, dkk. (2024) dan sebagian hasil Zahra, dkk. (2026) menunjukkan Transformer unggul, namun Latifah, dkk. (2026) menunjukkan model klasik tetap kompetitif bahkan lebih efisien pada dataset kecil-menengah. Pada sisi rekayasa perangkat lunak, Lhoest, dkk. (2021) menyediakan fondasi standardisasi data, Jartarghar, dkk. menyediakan fondasi rekayasa antarmuka, dan Maulyanda dan Nazhifah (2025) menyediakan preseden integrasi SVM ke FastAPI meskipun hanya pada satu model dan satu domain. Tidak ada satu pun dari kesembilan penelitian ini yang menggabungkan seluruh aspek tersebut (validasi algoritma ganda, standardisasi data, REST API , dan antarmuka pengguna) ke dalam satu sistem utuh yang siap pakai; sebagian besar berhenti pada tahap pelaporan metrik di dalam artikel ilmiah. Posisi penelitian ini adalah mengisi celah tersebut: menguji ulang Naive Bayes dan SVM pada data ulasan berbahasa Indonesia yang terstandarisasi dari Hugging Face Datasets , kemudian membungkus hasilnya menjadi REST API FastAPI dan dashboard Next.js yang dilengkapi lapisan interpretasi berbasis Large Language Model, sebagai satu kesatuan sistem SentimenAI yang dapat langsung digunakan, bukan sekadar dilaporkan.

[Section] Kajian Teori dan Teknologi Pendukung
[Subsection] Analisis Sentimen
[Standard] Analisis sentimen adalah cabang dari Natural Language Processing (NLP) yang bertujuan mengidentifikasi dan mengekstraksi opini, emosi, atau sikap yang terkandung dalam suatu teks, kemudian mengklasifikasikannya ke dalam kategori tertentu, misalnya positif, negatif, atau netral. Dalam konteks e-commerce , analisis sentimen banyak diterapkan pada ulasan produk untuk mengetahui kecenderungan kepuasan pelanggan secara agregat tanpa harus membaca setiap ulasan satu per satu, sebagaimana ditunjukkan pada seluruh penelitian terdahulu di Sub-bab 2.1.
[Subsection] Text Preprocessing
[Standard] Text preprocessing adalah rangkaian tahapan yang mengubah teks mentah menjadi bentuk yang lebih terstruktur dan siap diproses oleh algoritma machine learning . Berdasarkan praktik yang diterapkan Sanjaya, dkk. (2023), Apriyani, dkk. (2024), maupun Zahra, dkk. (2026), tahapan preprocessing yang umum diterapkan pada teks berbahasa Indonesia meliputi:
[Quote] - Case folding , yaitu penyeragaman huruf menjadi huruf kecil (lowercase) agar kata yang sama tidak dianggap berbeda hanya karena perbedaan kapitalisasi.
[Quote] - Penghapusan karakter khusus, yaitu menghilangkan tanda baca, angka, dan simbol non-alfanumerik menggunakan pencocokan pola (regular expression) yang tidak relevan terhadap makna sentimen.
[Quote] - Stopword removal , yaitu penghapusan kata-kata umum yang tidak memiliki bobot makna signifikan terhadap sentimen, seperti dan , yang , dan di , menggunakan kamus stopword bahasa Indonesia.
[Quote] - Stemming , yaitu proses pengubahan kata berimbuhan menjadi kata dasarnya, misalnya kata pengiriman menjadi kirim , untuk mengurangi variasi bentuk kata dari akar kata yang sama.

[Subsection] Support Vector Machine (SVM)
[Standard] Support Vector Machine adalah algoritma klasifikasi yang bekerja dengan mencari hyperplane pemisah optimal antar kelas dengan margin sebesar mungkin. Untuk data berdimensi tinggi seperti representasi TF-IDF pada teks, kernel linear (LinearSVC) umumnya sudah cukup memadai tanpa memerlukan transformasi kernel non-linear, sebagaimana diterapkan pada penelitian Danyal, dkk. (2023) dan Zahra, dkk. (2026). Parameter C mengatur toleransi terhadap kesalahan klasifikasi pada data latih; nilai C yang lebih besar membuat model lebih ketat dalam meminimalkan kesalahan klasifikasi namun berisiko overfitting , sedangkan nilai C yang lebih kecil memberi toleransi margin yang lebih lebar. Penelitian ini menggunakan C=1,0 sebagai nilai default yang umum digunakan pada penelitian pembanding.
[Subsection] TF-IDF (Term Frequency-Inverse Document Frequency)
[Standard] TF-IDF adalah metode pembobotan kata yang menilai seberapa penting suatu kata pada suatu dokumen relatif terhadap keseluruhan korpus dokumen. Nilai TF-IDF suatu kata w pada dokumen d dirumuskan sebagai:
[Standard] TF-IDF(w,d) = TF(w,d) × log(N / DF(w))
[Standard] dengan TF(w,d) adalah frekuensi kemunculan kata w pada dokumen d, N adalah jumlah total dokumen, dan DF(w) adalah jumlah dokumen yang mengandung kata w. Kata yang sering muncul di hampir seluruh dokumen (seperti stopword yang lolos filtering) akan memiliki bobot IDF yang rendah, sedangkan kata yang jarang muncul namun konsisten pada kelas tertentu akan memiliki bobot lebih tinggi. Penelitian ini mengikuti pendekatan Zahra, dkk. (2026) yang menggunakan kombinasi unigram dan bigram (ngram_range=(1,2)) dengan batas maksimum 10.000 fitur, guna menangkap frasa dua kata yang relevan seperti tidak bagus yang maknanya berbeda dari kata bagus saja.
[Subsubsection] Justifikasi Pemilihan TF-IDF
[Standard] Selain TF-IDF, representasi fitur teks yang umum digunakan pada penelitian NLP modern antara lain Bag-of-Words (BoW) sederhana, word embeddings terlatih seperti Word2Vec atau FastText, dan contextual embeddings dari model Transformer seperti BERT. Penelitian ini secara khusus memilih TF-IDF, bukan tanpa pertimbangan, dengan tiga alasan utama. Pertama, dibandingkan BoW yang hanya menghitung frekuensi mentah, TF-IDF memberi bobot lebih rendah pada kata yang muncul di hampir seluruh dokumen (melalui komponen IDF), sehingga kata-kata umum yang tidak diskriminatif terhadap sentimen secara otomatis diberi bobot lebih kecil tanpa perlu daftar stopword yang sepenuhnya manual. Kedua, dibandingkan word embeddings seperti Word2Vec, TF-IDF tidak memerlukan korpus pelatihan tambahan yang besar untuk menghasilkan representasi vektor kata yang bermakna, sehingga lebih sesuai untuk dataset penelitian ini yang berskala menengah (10.192 data). Ketiga, dan yang paling menentukan secara praktis, TF-IDF menghasilkan representasi vektor yang secara native kompatibel dengan Multinomial Naive Bayes dan LinearSVC yang menjadi fokus perbandingan penelitian ini (Sub-bab 1.2), sedangkan representasi dense embeddings umumnya lebih relevan dipasangkan dengan model neural. Pemilihan TF-IDF dengan demikian bukan karena mengabaikan kemajuan representasi fitur berbasis embeddings, melainkan karena representasi tersebut adalah representasi yang paling konsisten secara metodologis dengan kedua algoritma yang menjadi objek penelitian, sekaligus paling efisien secara komputasi untuk dibungkus ke dalam layanan REST API dengan waktu respons rendah (dibuktikan pada Sub-bab 4.7).

[Standard] SQLite adalah sistem manajemen basis data relasional yang bersifat server less dan menyimpan seluruh data dalam satu berkas tunggal pada disk. Karakteristik ini menjadikannya pilihan yang tepat untuk sistem berskala kecil-menengah seperti SentimenAI, karena tidak memerlukan proses instalasi server basis data terpisah, namun tetap mendukung operasi CRUD (Create, Read, Update, Delete) standar melalui bahasa SQL.
[Subsubsection] Justifikasi Pemilihan SQLite
[Standard] Dibandingkan basis data server seperti PostgreSQL atau MySQL, SQLite dipilih karena beban tulis (write load) pada tabel riwayat_analisis (Kode 3.2) bersifat rendah dan tidak konkuren dalam skala besar, mengingat sistem ini dirancang untuk digunakan oleh pelaku usaha e-commerce skala kecil-menengah (Sub-bab 1.5.2). Pemilihan ini turut didukung hasil pengujian performa Nugraha dan Susetyo (2023), yang membuktikan SQLite secara konsisten lebih unggul dibandingkan basis data kolumnar seperti DuckDB pada operasi transaksional (insert, update, delete, dan select), yaitu jenis operasi yang paling dominan pada tabel riwayat_analisis sistem ini, sedangkan keunggulan basis data kolumnar seperti DuckDB baru terasa pada beban kerja analitik agregat berskala besar yang bukan menjadi kebutuhan utama penelitian ini. Konsekuensi dari pilihan ini, yaitu keterbatasan SQLite dalam menangani banyak penulisan data secara bersamaan (concurrent write), diakui sebagai batasan dan didiskusikan lebih lanjut sebagai saran pengembangan pada Sub-bab 5.3.
[Subsection] Metrik Evaluasi Model Klasifikasi
[Standard] Evaluasi performa model klasifikasi pada penelitian ini, sejalan dengan pendekatan yang diterapkan pada seluruh penelitian pembanding di Sub-bab 2.1, menggunakan empat metrik yang diturunkan dari confusion matrix, yaitu:
[Quote] - Akurasi = (TP + TN) / (TP + TN + FP + FN), mengukur proporsi prediksi benar secara keseluruhan.
[Quote] - Presisi = TP / (TP + FP), mengukur ketepatan model ketika memprediksi kelas positif.
[Quote] - Recall = TP / (TP + FN), mengukur kemampuan model menemukan seluruh data kelas positif yang sebenarnya.
[Quote] - F1-Score = 2 × (Presisi × Recall) / (Presisi + Recall), merupakan rata-rata harmonik presisi dan recall yang menyeimbangkan kedua metrik tersebut.
[Subsection] Large Language Model (LLM)
[Standard] Large Language Model adalah model bahasa berskala besar yang dilatih pada korpus teks masif sehingga mampu memahami dan menghasilkan teks secara kontekstual. Pada sistem SentimenAI, LLM digunakan bukan sebagai model klasifikasi sentimen, melainkan sebagai lapisan interpretasi tambahan pada fitur Generate Insight, yang menerima konteks berupa data statistik dan hasil evaluasi model yang telah ada, kemudian menyusun jawaban naratif atas pertanyaan pengguna terkait strategi maupun interpretasi data.

[Subsubsection] Justifikasi Pemilihan Model ADDIE
[Standard] Dua model metodologi lain yang lazim digunakan pada penelitian machine learning adalah CRISP-DM (Cross-Industry Standard Process for Data Mining) dan Design Science Research (DSR). Perlu dijelaskan secara eksplisit mengapa ADDIE dipilih alih-alih keduanya. CRISP-DM, dengan enam fase (business understanding, data understanding, data preparation, modeling, evaluation, deployment ), sangat sesuai apabila fokus penelitian murni pada siklus data dan model. Namun, penelitian ini tidak berhenti pada model machine learning saja: ruang lingkupnya juga mencakup perancangan dan pengembangan REST API serta dashboard antarmuka pengguna secara utuh (Sub-bab 1.4 poin 3 dan 4), yang merupakan aktivitas rekayasa perangkat lunak (software engineering) di luar cakupan enam fase CRISP-DM. Design Science Research, di sisi lain, lebih menekankan pada kontribusi berupa artefak baru yang diuji secara iteratif untuk memecahkan masalah kelas tertentu, sesuai untuk penelitian yang berfokus pada novelty artefak; namun DSR tidak secara eksplisit menyediakan struktur tahapan evaluasi berlapis (black box, white box, cross validation ) yang dibutuhkan penelitian ini untuk memverifikasi baik sisi model maupun sisi sistem. ADDIE dipilih karena kelima fasenya (Analysis, Design, Development, Implementation, Evaluation) memetakan secara natural baik pada siklus pengembangan model machine learning maupun pada siklus pengembangan sistem REST API dan dashboard sebagai satu kesatuan, sebagaimana ditunjukkan pada pemetaan tahapan Sub-bab 3.1.1 hingga 3.1.5 yang mencakup kedua sisi tersebut secara eksplisit, sehingga lebih merepresentasikan cakupan penelitian ini yang bersifat end-to-end (Sub-bab 1.1) dibandingkan CRISP-DM yang hanya berfokus pada data dan model, maupun DSR yang lebih menekankan kontribusi artefak daripada tahapan pengembangan praktis.

[Subsubsection] Analisis Kualitas Dataset
[Standard] Selain EDA kuantitatif di atas, perlu dilakukan pemeriksaan kualitatif terhadap isi dataset untuk mengidentifikasi potensi persoalan yang dapat memengaruhi validitas hasil penelitian. Pemeriksaan manual terhadap sampel data menemukan tiga catatan penting. Pertama, dan yang paling perlu digarisbawahi secara jujur, isi ulasan pada dataset sepidmnorozy/Indonesian_sentiment ternyata didominasi ulasan tempat makan dan kuliner (contoh: bubur ayam yang lumayan rekomendasi di sekitaran Bandung , menu bebek relatif jarang di Bandung ), bukan murni ulasan produk e-commerce dalam pengertian barang yang dikirim dan diterima pembeli. Nama dataset pada Hugging Face Hub tidak secara eksplisit menyatakan domain spesifik ini, sehingga penelitian ini perlu mencatat secara transparan bahwa istilah ulasan e-commerce pada judul dan rumusan masalah merujuk pada karakteristik ulasan berbasis pengalaman konsumen secara umum (termasuk kuliner dan jasa yang lazim dipasarkan melalui platform digital), bukan secara sempit terbatas pada ulasan barang fisik. Implikasi metodologis dari temuan ini dibahas lebih lanjut sebagai bagian dari Threats to Validity pada Sub-bab 5.3. Kedua, ditemukan sejumlah data berupa satu kata tunggal yang ambigu tanpa konteks memadai, misalnya gagal (berlabel negatif), tulus dan damai (berlabel positif), yang secara linguistik sulit dibedakan sentimennya tanpa konteks kalimat yang lebih panjang, dan berkontribusi pada kesalahan klasifikasi sebagaimana ditemukan pada error analysis di Sub-bab 4.8. Ketiga, distribusi kelas yang tidak seimbang (64,7% berbanding 35,3%) berpotensi membuat model lebih condong memprediksi kelas mayoritas (positif), sebuah kecenderungan yang perlu diperhatikan saat menginterpretasikan metrik akurasi secara terpisah dari precision dan recall per kelas pada Sub-bab 4.7.

[Subsection] K-Fold Cross Validation

Kedua, secara praktis, sistem SentimenAI yang telah dibangun (dengan pipeline preprocessing lengkap, akurasi 88,26% pada pengujian ablasi ini menggunakan split yang sama) tetap dipertahankan sebagaimana adanya karena mengubah pipeline preprocessing pada tahap ini akan mengubah seluruh model yang telah dievaluasi menyeluruh pada Sub-bab 4.10, namun perbaikan pipeline preprocessing agar mengecualikan kata negasi dari daftar stopword dicatat secara eksplisit sebagai saran pengembangan prioritas tinggi pada Sub-bab 5.2.

Temuan ini memperkuat argumen Latifah, dkk. (2026) bahwa untuk dataset berskala kecil-menengah, model klasik dengan representasi TF-IDF yang tepat tetap menjadi pilihan yang efisien, tanpa perlu menanggung kompleksitas komputasi dan kebutuhan data besar yang dituntut model Transformer untuk menghasilkan performa optimal.
[Standard] Dengan demikian, hasil penelitian ini tidak hanya menjawab rumusan masalah nomor 2 secara mandiri, tetapi juga memperkaya peta perdebatan Naive Bayes versus SVM yang telah dibuka pada Sub-bab 2.1, dengan menempatkan titik data baru yang spesifik pada konteks dataset ulasan e-commerce Indonesia berskala menengah dari Hugging Face Datasets , sebuah konteks yang belum pernah diuji secara spesifik oleh kesembilan penelitian terdahulu.
[Section] Pembahasan Hasil Pengujian Fungsional
[Standard] Hasil pengujian fungsional pada Sub-bab 4.4 hingga 4.7 menunjukkan sistem SentimenAI berhasil memenuhi seluruh kebutuhan fungsional yang dirancang pada Bab 3, termasuk pada dua skenario kondisi tepi ( input kosong dan kegagalan layanan Gemini API) yang justru menjadi indikator ketahanan sistem, bukan sekadar kebenaran jalur normal. Keberadaan fitur Generate Insight berbasis Gemini API memberi nilai tambah signifikan karena mengubah keluaran sistem dari sekadar label dan angka statis menjadi rekomendasi naratif yang dapat langsung ditindaklanjuti pengguna non-teknis, sejalan dengan manfaat praktis pada Sub-bab 1.5.2, dengan mekanisme fallback berbasis data lokal yang memastikan ketergantungan terhadap layanan pihak ketiga telah dimitigasi secara memadai.
[Section] Kesimpulan Hasil Pengujian
[Standard] Secara keseluruhan, empat lapis pengujian yang dilakukan pada bab ini, black box testing , white box testing , k-fold cross validation , dan pengujian integrasi, secara konsisten membuktikan bahwa sistem SentimenAI berfungsi sesuai rancangan, tahapan preprocessing bekerja benar pada level internal, dan model SVM (88,44%, stabil pada validasi silang dengan standar deviasi ±0,29%) unggul secara meyakinkan atas Naive Bayes (87,56%) pada konteks data penelitian ini. Pembahasan lebih lanjut mengenai bagaimana seluruh temuan ini menjawab rumusan masalah penelitian secara utuh disajikan pada Bab 5.
[Chapter] Kesimpulan
[Section] Kesimpulan
[Standard] Penelitian ini berangkat dari satu keresahan yang diuraikan sejak Sub-bab 1.1, yaitu inkonsistennya hasil perbandingan Naive Bayes dan SVM pada penelitian-penelitian terdahulu (Sub-bab 2.1), serta kecenderungan penelitian analisis sentimen berhenti pada tahap pelaporan angka akurasi tanpa dibungkus menjadi sistem yang benar-benar dapat digunakan. Berdasarkan seluruh tahapan metodologi pada Bab 3 dan hasil pengujian pada Bab 4, kelima rumusan masalah pada Sub-bab 1.2 dapat dijawab sebagai berikut:
[Quote] 1. Metode Multinomial Naive Bayes dan Support Vector Machine (LinearSVC) berhasil diimplementasikan secara sistematis untuk klasifikasi sentimen ulasan e-commerce berbasis dataset sepidmnorozy/Indonesian_sentiment dari Hugging Face Datasets , melalui pipeline preprocessing empat tahap ( case folding , penghapusan karakter, stopword removal PySastrawi, dan stemming ) yang telah diverifikasi kebenarannya secara internal melalui white box testing pada Sub-bab 4.6, serta ekstraksi fitur TF-IDF dengan konfigurasi ngram_range=(1,2) dan max_features=10.000.
[Quote] 2. SVM terbukti unggul secara konsisten atas Naive Bayes pada seluruh metrik evaluasi (akurasi 88,44% berbanding 87,56%, presisi 88,35% berbanding 87,46%, recall 88,44% berbanding 87,56%, F1-score 88,36% berbanding 87,48%) dan tetap stabil pada pengujian 5-fold cross validation (standar deviasi ±0,29%). Hasil ini konsisten dengan temuan Apriyani, dkk. (2024) dan Zahra, dkk. (2026) pada data berbahasa Indonesia, sekaligus menegaskan bahwa keunggulan Naive Bayes pada penelitian Sanjaya, dkk. (2023) bersifat spesifik terhadap karakteristik dataset Shopee yang digunakan, bukan keunggulan mutlak yang berlaku universal, sejalan dengan simpulan Danyal, dkk. (2023) mengenai pengaruh ukuran dan karakteristik dataset terhadap performa algoritma.
[Quote] 3. REST API berbasis FastAPI 0.109.0 berhasil dirancang dan diimplementasikan dengan enam belas endpoint layanan (Tabel 3.1), mencakup prediksi tunggal, dual model, preprocessing step-by-step, batch CSV, riwayat, statistik, evaluasi, dan tanya-jawab Generate Insight, yang seluruhnya terbukti berfungsi sesuai spesifikasi melalui black box testing dan pengujian integrasi pada Sub-bab 4.4 dan 4.7.
[Quote] 4. Dashboard interaktif berbasis Next.js 14 berhasil dikembangkan dengan enam tab fungsional (Analisis, Dataset , Evaluasi, Trend, Rekomendasi, Riwayat) dan halaman Generate Insight yang terintegrasi Gemini API, terbukti mampu menyajikan visualisasi real-time dan interpretasi naratif kontekstual bagi kebutuhan manajemen internal, termasuk mekanisme fallback berbasis data lokal ketika layanan eksternal tidak tersedia, sebagaimana dibuktikan pada skenario pengujian nomor 8 dan 9 di Tabel 4.1.
[Quote] 5. Sistem penyimpanan riwayat analisis menggunakan SQLite berhasil dirancang sebagai basis data permanen yang tidak hilang saat server di-restart, dapat diakses melalui endpoint /riwayat dan /statistik, dan terbukti berfungsi sebagai basis konteks data real-time bagi fitur Generate Insight, sebagaimana dibuktikan pada skenario pengujian nomor 10 di Tabel 4.1.
[Standard] Di luar kelima rumusan masalah tersebut, penelitian ini turut memberi tiga kontribusi tambahan hasil audit metodologi yang memperkuat kredibilitas akademik penelitian. Pertama, hyperparameter tuning menggunakan GridSearchCV (Sub-bab 4.10.2) membuktikan bahwa parameter default yang digunakan sistem (alpha=0,1 dan C=1,0) sudah berada di sekitar wilayah optimal, dengan potensi perbaikan tipis pada alpha=0,5 (87,95%) dan C=0,5 (89,19%). Kedua, studi ablasi preprocessing (Sub-bab 4.11) mengungkap temuan penting bahwa stopword removal berbasis PySastrawi menurunkan akurasi karena turut menghapus kata negasi ( tidak , kurang , belum ), sebuah kontribusi metodologis yang relevan bagi penelitian sentiment analysis Bahasa Indonesia secara umum, tidak terbatas pada penelitian ini saja. Ketiga, error analysis (Sub-bab 4.12) mengidentifikasi tiga pola kesalahan klasifikasi yang konsisten (ulasan satu kata, struktur kalimat kontras, dan sentimen negatif implisit), yang menjelaskan secara kualitatif mengapa akurasi model secara teoritis dibatasi pada kisaran 88-89% pada dataset ini. Hasil pada Tabel 4.14 menempatkan titik data baru pada peta perdebatan Naive Bayes versus SVM secara spesifik pada konteks dataset ulasan berbahasa Indonesia dari Hugging Face Datasets , sekaligus membuktikan melalui sistem SentimenAI yang beroperasi penuh dan diukur waktu responsnya (median 6,51 ms, Sub-bab 4.8) bahwa model klasik yang telah lama diteliti secara akademik tetap layak dan efisien untuk dibungkus menjadi layanan produksi, tanpa harus menunggu kematangan model Transformer yang menuntut sumber daya jauh lebih besar. Dengan demikian, dapat disimpulkan bahwa sistem SentimenAI yang dikembangkan pada penelitian ini layak digunakan sebagai alat bantu analisis sentimen yang akurat, teruji secara berlapis (black box, white box, boundary, cross validation , dan heuristic usability ), dan informatif, serta berhasil mencapai seluruh tujuan penelitian yang ditetapkan pada Sub-bab 1.4.
[Section] Threats to Validity
[Standard] Sebagaimana lazimnya penelitian empiris, hasil penelitian ini perlu dibaca dengan memperhatikan sejumlah ancaman terhadap validitas yang diidentifikasi secara jujur sebagai berikut, mengikuti kerangka validitas internal, eksternal, dan konstruk yang umum digunakan pada penelitian rekayasa perangkat lunak dan machine learning .
[Subsection] Validitas Internal
[Standard] Ancaman validitas internal utama pada penelitian ini adalah domain isi dataset . Sebagaimana diungkap pada analisis kualitas dataset (Sub-bab 3.1.1.2), pemeriksaan manual terhadap sampel data menemukan bahwa dataset sepidmnorozy/Indonesian_sentiment yang digunakan didominasi ulasan tempat makan dan kuliner, bukan murni ulasan barang e-commerce dalam pengertian sempit. Hal ini berarti hasil perbandingan Naive Bayes dan SVM pada penelitian ini paling valid untuk digeneralisasi pada ulasan berbasis pengalaman konsumen secara umum, dan perlu kehati-hatian bila hendak digeneralisasi secara sempit hanya pada ulasan barang fisik e-commerce . Ancaman kedua adalah evaluasi model yang hanya menggunakan satu skema pembagian data latih-uji dari dataset (meskipun telah diperkuat dengan 5-fold cross validation pada Sub-bab 4.10.1), sehingga variasi hasil akibat pengacakan data (random seed) pada skema pembagian yang berbeda belum sepenuhnya dieksplorasi.
[Subsection] Validitas Eksternal
[Standard] Hasil penelitian ini diperoleh dari satu dataset spesifik (10.192 data dari sepidmnorozy/Indonesian_sentiment) dan satu konfigurasi preprocessing serta representasi fitur (TF-IDF, ngram 1-2, 10.000 fitur). Generalisasi hasil ke dataset ulasan e-commerce lain dengan karakteristik berbeda, misalnya ulasan berbahasa daerah campuran (code-switching) atau ulasan dengan volume data yang jauh lebih besar sebagaimana pada penelitian Zahra, dkk. (2026), perlu dilakukan dengan pengujian ulang, bukan diasumsikan otomatis berlaku sama, sejalan dengan simpulan Danyal, dkk. (2023) mengenai sensitivitas performa algoritma terhadap karakteristik dataset .
[Subsection] Validitas Konstruk
[Standard] Evaluasi usability pada Sub-bab 4.9 menggunakan heuristic evaluation yang dilakukan oleh peneliti sendiri sebagai evaluator tunggal, bukan User Acceptance Testing dengan responden pengguna nyata dari kalangan pelaku usaha e-commerce . Hasil evaluasi usability tersebut karenanya mengukur konstruk kepatuhan terhadap prinsip desain baku dan bukan konstruk kepuasan pengguna aktual , sehingga tidak dapat menggantikan sepenuhnya validasi penerimaan pengguna yang idealnya dilakukan melalui studi lapangan dengan responden nyata, sebagaimana dicatat sebagai saran pengembangan pada Sub-bab 5.3.
[Section] Saran
[Standard] Berdasarkan hasil penelitian, pengujian, dan batasan masalah pada Sub-bab 1.3, serta Threats to Validity pada Sub-bab 5.2, berikut saran bagi pengembangan penelitian selanjutnya:
[Quote] 1. Perbaiki daftar stopword PySastrawi dengan mengecualikan kata negasi ( tidak , kurang , belum , jangan ) sebelum diterapkan pada pipeline preprocessing, mengingat temuan ablasi pada Sub-bab 4.11 membuktikan penghapusan kata negasi menurunkan akurasi hingga 3,36 poin persentase; perbaikan ini menjadi prioritas tertinggi karena berdampak langsung pada akurasi klasifikasi.
[Quote] 2. Perbarui parameter model menjadi alpha=0,5 (Naive Bayes) dan C=0,5 (SVM) sesuai hasil GridSearchCV pada Sub-bab 4.10.2 yang terbukti memberi peningkatan akurasi tipis namun konsisten pada data uji.
[Quote] 3. Tambahkan validasi teks pasca-preprocessing pada endpoint /prediksi (bukan hanya validasi teks mentah) untuk mengatasi temuan pada Sub-bab 4.5, yaitu input berupa angka/simbol/emoji yang menghasilkan teks bersih kosong namun tetap diberi label prediksi yang tidak bermakna.
[Quote] 4. Lakukan User Acceptance Testing dengan responden nyata dari kalangan pelaku usaha e-commerce untuk melengkapi heuristic evaluation pada Sub-bab 4.9 yang masih bersifat evaluasi mandiri peneliti, sebagaimana dicatat sebagai ancaman validitas konstruk pada Sub-bab 5.2.3.
[Quote] 5. Uji ulang perbandingan Naive Bayes dan SVM pada dataset ulasan yang secara eksplisit berdomain barang e-commerce (bukan dominan kuliner sebagaimana temuan Sub-bab 3.1.1.2), misalnya melalui web scraping langsung dari Tokopedia atau Shopee, untuk memperkuat validitas eksternal hasil penelitian.
[Quote] 6. Uji perbandingan Naive Bayes dan SVM dengan pendekatan fine-tuning IndoBERT secara langsung pada dataset yang sama, mengingat penelitian Zahra, dkk. (2026) menunjukkan bahwa fine-tuning yang kurang optimal dapat membuat IndoBERT kalah dari SVM, sehingga menarik diuji apakah pola serupa berlaku pada dataset penelitian ini.
[Quote] 7. Perluas klasifikasi menjadi tiga kelas dengan kategori netral sebagaimana diterapkan Ali, dkk. (2024) dan Zahra, dkk. (2026), disertai penanganan ketidakseimbangan kelas (64,7% berbanding 35,3% pada Sub-bab 3.1.1.1) menggunakan class_weight balanced .
[Quote] 8. Lakukan deployment ke layanan produksi seperti Vercel ( frontend ) dan Hugging Face Spaces atau Docker ( backend ), sebagaimana dicontohkan Zahra, dkk. (2026), disertai load testing untuk mengukur kapasitas maksimum permintaan API secara bersamaan, melengkapi pengukuran response time pada kondisi beban rendah di Sub-bab 4.8.
[Quote] 9. Eksplorasi model bahasa lokal ( self-hosted LLM) sebagai alternatif Gemini API pada fitur Generate Insight untuk mengurangi ketergantungan pada layanan pihak ketiga dan risiko keterbatasan kuota di masa mendatang.
